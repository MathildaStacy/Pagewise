# Pagewise 伴读引擎规格

> 版本 0.1 · 2026-10-28 · 配套：[产品设计](PRODUCT_DESIGN.md)
> 伴读引擎是纯 TypeScript 模块，不依赖 UI。本文规定它的数据、算法和与 AI 的约定，M1–M4 按它实现和测试。

## 1. 数据模型

```
Book        id · title · author · format(pdf|epub) · sha256 · pages · parse_model(vlm|pipeline) · status
BookFile    book_id · part_no · page_from · page_to · mineru_task_id · status · error_code
Block       id · book_id · seq · page · bbox[x0,y0,x1,y1] · type(title|text|equation|image|table|list|caption)
            · level(标题层级, 仅 title) · text · latex · image_path · section_id
Section     id("3.5.2") · book_id · parent_id · level(1 章 / 2 节 / 3 小节) · title · block_from · block_to
            · page_from · page_to · chars · parts(讲解段数) · status(new|learning|done) · summary · source(auto|bookmark|manual)
StudyState  book_id · main(section_id, part) · detours[stack of section_id] · last_active_at
Message     id · book_id · section_id · role · content · citations[block_id] · is_detour · created_at
SectionNote section_id · summary · qa[{q, a, from_section}] · stuck[{text, resolved}] · user_text
Card        id · section_id · front · back · box(1–5) · due_at
ReviewLog   card_id · rated(again|hard|good) · at
Highlight   block_id · range · color · note
```

`Block` 直接来自 MinerU 的内容块 JSON（每块有页码和位置框）；`seq` 是全书顺序号，分片解析后按原书页码重排、重新编号。

## 2. 解析流水线

```
选择文件
 → 计算 SHA-256；已有同哈希的书 → 直接打开
 → 读页数、大小、文字层、书签（PdfRenderer + 本地解析）
 → 分片：每片 ≤ 600 页且 ≤ 200 MB；从"优先页"所在片开始排队
 → 用户确认上传
 → 每片：申请上传地址 → 上传 → 轮询任务状态（指数退避，最长 30 秒一次）→ 下载结果包
 → 解包：Markdown、内容块 JSON、图片 → 页码加上片偏移 → 写入 Block
 → 该片完成即构建 / 更新地图（§3），已就绪的章节可以开始学
 → 全部完成 → 地图与书签做最终核对 → status = ready
```

| 错误 | 处理 |
| --- | --- |
| Token 无效或过期 | 停止队列，提示去「我的 → 解析服务」更新 Token，更新后从失败片继续 |
| 当日高优先级额度用完 | 不拦截，提示"会排队变慢"，可选择明天再解析 |
| 单片超限（页数 / 大小） | 自动把该片再对半拆 |
| 网络中断 / 轮询超时 | 保留任务 ID，恢复网络后继续轮询，不重复上传 |
| 解析结果为空页过多（> 20%） | 提示可能是扫描版，建议打开 OCR 重新解析该片 |

接口细节（字段名、限额）以 MinerU 官方文档为准，M1 开始前再核对一次。

## 3. 地图构建

1. 取所有 `type = title` 的块，用编号正则 `^(\d+)(\.\d+){0,2}\s` 和 `第\d+章` 识别章、节、小节；没有编号的标题按 MinerU 给的 `level` 挂到最近的上级。
2. 每个小节的范围 = 从它的标题块到下一个同级或更高级标题块之前。
3. 和 PDF 书签对照（标题去空白后做编辑距离匹配，页码差 ≤ 1 视为一致）：
   - 书签有、解析没有 → 标黄"可能漏识别"，给出书签所在页，用户可一键补上。
   - 解析有、书签没有 → 正常保留（书签往往只到二级）。
   - 层级不同 → 以书签为准，标黄让用户确认。
4. 叶子小节 > 4000 字：在段落边界切成若干段，每段 1500–3000 字，公式、算法框图、图和它的说明不切开。
5. 叶子小节 < 300 字：并入后一个兄弟小节（章首引言并入第一节）。
6. 用户手动修改的小节 `source = manual`，重新解析时保留。

## 4. 讲解协议

写在系统提示里、可被讲解偏好覆盖的规则：

1. 每段讲解的顺序：直觉 → 定义 / 公式 / 算法 → 书里的例子 → 一个检查问题。
2. 只讲当前段的内容；当前段讲完前不主动跳到下一段。
3. 术语第一次出现时中英对照，例如"可容许的（admissible）"。
4. 引用：每个依赖书中内容的说法，后面写引用标记 `[[b:<block_id>]]`。只能引用本轮上下文里出现过的块。
5. 书里没有、是你自己补充的内容，明确说"书里没有直接讲，这是补充"。
6. 用户答错检查题时，换一个角度再讲一次，而不是重复原话。
7. 用户问到其他小节的内容时，先调用 `load_section`，不要凭记忆回答。

## 5. 上下文组装

每轮请求按顺序拼装，缓存断点放在第 2 层之后：

| 层 | 内容 | 典型大小 | 缓存 |
| --- | --- | --- | --- |
| 1 讲解规则 | §4 + 讲解偏好 | 1k tokens | ✓ |
| 2 书的地图 | 全书目录（编号、标题、页码）+ 已学小节摘要 | 2–5k | ✓（学完一节才变） |
| 3 当前原文 | 主线所在段的全部内容块（含块 ID、页码、公式 LaTeX、图片说明） | 2–5k | 同一段内命中 |
| 4 学习记录 | 本书进度、该节和相关节的卡点、最近 10 个问题 | 0.5–1k | |
| 5 按需加载 | 岔路原文 / 搜索结果（工具返回） | 0–8k | |
| 6 最近对话 | 当前段的对话；更早的只保留摘要 | 1–4k | |

预算：单轮输入超过 24k tokens 时，先压缩第 6 层，再把第 5 层里最早的岔路原文换成它的摘要。图片默认只给说明文字；用户问到图本身时才把图片发给支持视觉的模型。

## 6. 工具

只读工具，AI 可以直接调用，每轮最多 4 次：

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `load_section` | `id`，可选 `part` | 该小节（或段）的全部内容块 |
| `search_book` | `query`，可选 `chapter` | FTS 命中的前 8 个块：块 ID、页码、所在小节、片段 |
| `get_figure` | `block_id` | 图片和它的说明文字 |
| `get_notes` | `section_id` | 该节的摘要、问答、卡点 |

写操作，AI 只能提议，界面上出现确认卡片，用户确认后才生效：

| 工具 | 作用 |
| --- | --- |
| `propose_summary` | 本节摘要草稿 |
| `propose_cards` | 闪卡草稿（3–5 张） |
| `mark_stuck` | 记一个卡点 |
| `advance_progress` | 讲完当前段 / 当前节，移动主线指针 |

界面把每次工具调用显示成一行步骤，例如「读取 3.4.2 Dijkstra 算法或一致代价搜索（p.92–95）」。

## 7. 主线与岔路

```
                 用户问到别的小节 / 点"回到 X 节"
   ┌──────────┐  load_section(X)      ┌──────────────┐
   │ 主线讲解中 │ ───────────────────▶ │ 岔路 X（深度 1）│ ──▶ 岔路 Y（深度 2，最多）
   │ main=3.5.2│ ◀─────────────────── │ detours=[X]   │
   └──────────┘  点"回到主线"/         └──────────────┘
                 AI 判断岔路问题已答完并询问后用户同意
```

- 进入岔路不移动主线指针；岔路里的消息 `is_detour = true`，同时写进被问小节的 `SectionNote.qa`（`from_section` = 主线小节）。
- 回到主线时，AI 用一句话接上："回到 A\*：刚才讲到……"。
- 岔路深度到 2 时再问别的小节，先提示"要不要先回主线"。
- 用户在岔路里说"从这里开始学"，主线指针改到 X，原主线小节保持 `learning`。

## 8. 引用校验

- AI 输出里的 `[[b:<id>]]` 在显示前校验：块必须出现在本轮第 3 层或第 5 层上下文里。
- 通过：渲染成页码标签（如 `p.93`），点开跳到阅读器并高亮该块的位置框。
- 不通过：去掉标记，该句后面加灰色"未核实"。连续 3 轮出现未核实引用，自动在下一轮提示里重申规则 4。

## 9. 复习调度

用 5 个盒子的间隔重复（Leitner），简单、能解释：

| 盒子 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| 下次复习 | 1 天后 | 3 天后 | 7 天后 | 15 天后 | 30 天后 |

- 新卡进盒子 1。
- 「记得」→ 升一个盒子；「模糊」→ 留在原盒子；「忘了」→ 回盒子 1，并把这张卡对应的点加入卡点清单。
- 每天复习上限默认 30 张，超出的顺延。

## 10. 续学

打开一本书时，如果 `now - last_active_at ≥ 1 天`：

1. 取主线小节的已讲段摘要、未解决卡点、最后 3 个问题。
2. 让整理模型生成 ≤ 3 句的回顾，第一句说讲到哪，第二句说卡点，第三句问要不要先复习。
3. 显示在对话顶部，附「直接继续」「先复习卡点」两个按钮。不计入主线对话历史。

## 11. 测试用例来源

- 地图构建：《人工智能：现代方法（第4版）》第 3 章的真实解析结果，期望得到 6 个节、26 个小节，页码和书签一致。
- 引用校验：构造包含越界块 ID、不存在的块 ID、重复引用的回答。
- 岔路：进入 → 嵌套 → 超深度提示 → 回主线 → 从岔路改主线，检查指针和笔记写入。
- 复习：盒子升降和到期日期，跨时区、跨午夜。
