后续修复及复测见 [v0.0.17 阅读渲染修复](reader-rendering-fixes-v0.0.17.md)。下文保留 v0.0.16 的实际审查结果。

2026-11-02。结论：**五套皮肤的普通正文样本可读，但不能判定所有皮肤及书本内容渲染正常。** 已发现跨皮肤共用的公式、表格、HTML 上下标和横向手势问题；苹果风另有表格弹层透字、辅助小字对比度不足的问题。本轮是审查记录，未修改 App 代码、重解析书籍或发布新版本。

## 需要优先修复的共用问题

### P1：合法公式命令不受支持，直接露出 TeX 源码

实际 Release 中，利率讲义 p.17「7.4 多维曲线风险」的向量表达式显示为 `\boldsymbol { x } = ( x _ { 1 } , \dots , x _ { p } )`；同段梯度和 Hessian 公式能正常排版。在纸感、Win11 的实际界面复现，五套皮肤共用同一个 `MathView`，换肤不能解决。

生产离线 MathJax 3.2.2 仅启用 `base`、`ams`、`newcommand`（[copy-mathjax.js](../../scripts/copy-mathjax.js) 的 `window.MathJax.tex`）。`\boldsymbol` 等命令缺失时返回渲染失败，[MathView](../../src/ui/kit/base/content.tsx) 用等宽文本显示原 TeX。补齐常用命令支持应优先于调整皮肤字体；识别阶段已损坏的 TeX 还需要单独处理，不能靠加载命令包自动纠正。

### P1：表格单元格没有接入公式渲染

利率讲义 p.8「4.2 逐日期现金流表」在五套皮肤的浅、深色中均显示 `$T_1$`、`$T_2$`、`$D(T_2)$` 等原始字符串。[tableRows](../../src/features/study/presenters.ts) 去掉 HTML 标签后返回字符串，[ReaderView](../../src/ui/screens/ReaderView.tsx) 的表格预览和展开表格使用普通文本，没有经过富文本／数学渲染。

修复目标是让表格单元格保留并渲染数学含义，同时保持行列对应；只删除美元符号会掩盖问题。

### P1：表格横滑不可达，长公式横滑容易误触

- **表格**：纸感和 Win11 的 p.8 展开表格，右端列超出屏幕。纸感下在单元格、行间和页码处，分别以 160／300／1000 ms 横滑，多次操作后内容仍保持原位，看不到最右侧 `T_2` 列。Win11 样本同样未能横滑到右端。不能因为原生树标记 `HorizontalScrollView` 可滚动就判定通过。
- **长公式**：纸感 p.4 的 `D(T)=exp(…)` 公式，直接在符号上横滑时未移动，且可触发段落选中／操作浮层；改在公式下方的空白边距横滑后能看到右端。Win11 在公式中部横滑也未移动。因此不是公式内容全部丢失，而是手势命中区域不可靠，用户难以发现可用区域。

相关实现为 [MathView 与 BlockView](../../src/ui/kit/base/content.tsx) 的横向 `ScrollView`、外层 `Pressable`，以及 [ReaderView](../../src/ui/screens/ReaderView.tsx) 表格横向滚动嵌套 [Sheet 的 BottomSheetScrollView](../../src/ui/kit/base/overlays.tsx)。这是排查入口；具体手势冲突根因尚未通过代码修改实验确认。应以「直接在内容上滑动能看到末列／公式末尾，且不弹出段落操作」验收。

[横滑前后局部证据](evidence/skin-reading-v0.0.16/horizontal-gestures.jpg)。需要更正审查过程中的初步判断：**长公式不能笼统标为“可横滑，正常”**；本轮已复现命中区域问题。

### P2：正文 HTML 上下标作为文字显示

利率讲义 p.4「线性产品并不意味着价格对利率是直线」段落出现 `e−<sup>rT</sup>`。苹果风、Meta、Win11 样本可见原标签。共用的 [parseInline](../../src/core/markup/index.ts) 识别美元数学表达式、代码和粗体，但未处理这种 HTML 上下标。

应保留上标／下标语义后渲染，不能只删标签将指数变为普通正文。输入自身可能还有 OCR 数学错误，显示修复与内容校对要分别验证。

## 苹果风的额外问题

1. **P2，表格弹层透字。** 浅色、深色表格背景均可看到底层章节标题、段落和公式，形成两层文字叠在一起。[SkinProvider](../../src/ui/kit/SkinProvider.tsx) 在 Android 关闭 BlurView，但 [GlassSurface](../../src/ui/kit/base/overlays.tsx) 对苹果风仍使用半透明材质填充，缺少对应的不透明回退。应保留皮肤风格，同时保证弹层内容区可读。[浅深色局部对照](evidence/skin-reading-v0.0.16/glass-table-bleed.jpg)。
2. **P2，浅色辅助小字对比度不足。** `ink2 = rgba(60,60,67,.62)` 在白底上的对比度约 **3.62:1**，低于普通小字的 4.5:1；不涉及黑色主正文。现有 [contrast.test.ts](../../__tests__/ui/contrast.test.ts) 明确保留了该原型配色例外，因此测试通过并不等于这类文字达到 AA。

五套皮肤在浅深色的主正文 `paperInk/paper` 对比度约 11.77–21:1，公式 `ink/paper` 约 12.30–21:1。此次未发现主正文对比度不足；这些数值是当前 token 颜色计算，不是全 App 无障碍认证。

## 六本书公式兼容性扫描

复用已有入库快照，通过生产 `parse`、`displayTex` 提取正文／公式块里的数学表达式，使用与 APK 相同版本及包配置的 MathJax 生成 SVG 并检查错误。共 **9,463 次公式出现，5,883 个去重后的 TeX／显示模式组合**；其中 **220 个组合失败，对应 241 次出现**。

| 书籍 | 公式出现次数 | 渲染失败出现次数 | 涉及标注页数 |
| --- | ---: | ---: | ---: |
| ISLP | 3,402 | 23 | 21 |
| 机器学习实战，第 2 版 | 936 | 102 | 69 |
| 因子投资：方法与实践 | 2,856 | 97 | 39 |
| 打开量化投资的黑箱 | 105 | 0 | 0 |
| AFML | 1,780 | 18 | 12 |
| 利率模型讲义 | 384 | 1 | 1 |

220 个失败组合中，204 个首个错误为不支持 `\boldsymbol`；其余包括 `\hdots`、字体命令、其他未定义命令与括号不匹配。部分异常可能源自 OCR，不能一概归因于渲染器。该扫描不包含表格单元格，也不检测 SVG 裁切、手势和公式数学含义；**241 次失败不代表逐一在 App 中人工确认，9,222 次未报错也不代表 OCR 正确。** 原生界面已复现上述 p.17 的命令兼容问题。

## 验证记录与后续验收

执行了 `math`、`contrast`、`readerFidelity`、`readerAiSkins`、`math/assets` 五个相关测试套件：**168 项通过**。现有测试未覆盖本次真实内容中的命令缺失、表格公式、HTML 上下标和原生横滑行为，因此不应据此给出“全部正常”的结论。

后续修复按以下顺序验收：

1. 补齐实际书籍需要的公式命令，重新运行相同的六本扫描；对仍失败的表达式区分渲染兼容与源内容错误。
2. 表格、正文上下标接入保留语义的渲染；核对 p.4、p.8、p.17 的真实内容。
3. 在公式符号与表格单元格上直接横滑，确认末尾可达且不会误触段落菜单；覆盖五皮肤、深浅色和放大字号。
4. 修复苹果风无模糊时的弹层回退及小字对比度，再复测相同截图场景。

原始截图、原生 UI 树、手势脚本、公式错误明细和测试日志保存在 Git 忽略目录 `fixtures/private/downloads-20261102/skin-audit-v0.0.16/`。本文只附问题与样式的局部图，没有提交原书或完整解析文本。另见 [OCR 质量审查](ocr-quality-audit-20261102.md)：v0.0.16 开启 OCR 的新默认不修复这些渲染问题，也不会自动更新现有六本书的识别内容。
