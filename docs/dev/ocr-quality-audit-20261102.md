# 六本真实 PDF 的 OCR 质量复核

2026-11-02，基于 v0.0.15 的六本书完整导入结果。**确认存在会改变数学含义的识别错误，尤其是负号、变量、希腊字母和上下标。** 正文段落通常可读，但不能仅凭解析成功、公式能显示或引用能跳转，就认定适合直接用于公式推导。

本轮复用全部 18 个原始 MinerU 结果包和 21,908 个已入库内容块，扫描乱码、跨页标记与被过滤内容，并针对公式、双栏索引、脚注、旋转表格和扫描页查看原 PDF 图像。另选 7 页做 4 种配置的云端对照，共提交 28 个单页任务；三组 VLM 的 21 个结果已完成，7 个 pipeline 任务在最后查询时仍为 `pending`。没有重新上传六本全书，也没有替换现有书籍的内容和学习记录。

下文页码全部为 **PDF 物理页码，从 1 开始**。这是针对性视觉抽查和全量结构扫描，不是逐字校对，也不据此给出字符准确率。

## 更正：此前的“8 页 OCR 缺口”并不准确

检查 `layout.json` 的 `preproc_blocks`、`para_blocks`、`cross_page` 和 `lines_deleted` 后，确认其中 **7 页的内容已被 MinerU 合并到前页的段落或表格**，并未完全漏识别：

| 原内容所在页 | 内容在解析结果中的归属 |
| --- | --- |
| 机器学习实战 p.181、326、520、594、784 | 分别合入 p.180、325、519、593、783 的段落或脚注 |
| 因子投资 p.164 | 合入 p.163 的脚注 |
| AFML p.114 | 旋转表格的续表内容合入 p.113 的表格 |
| 机器学习实战 p.663 | `Vision 10, no.3 (2014): 177–243.` 被服务端标成 `header`，App 过滤页眉时丢掉这条可检索文本；原页图像仍保留 |

因此，正确结论是：**7 页存在跨页内容定位问题，1 页存在页眉误分类导致的文本遗漏。** 7 页合并内容仍在前页，可被检索；其原页图像自身没有独立可选文字。v0.0.15 的“此页文字未能识别”提示把这两种情况混在一起了。

全量原始布局中发现 **803 个含跨页续接标记的源块**：ISLP 210、机器学习实战 158、因子投资 183、黑箱 151、AFML 101、利率讲义 0。这不是 803 处 OCR 错误，也不是 803 页丢失。App 当前只保留合并块的起始页和边界框，导致原页定位不够准确。AFML p.370 的段落甚至跨过图页合回 p.368，不能简单把空块归到“上一页”。

后续若修复跨页定位，需要保存同一块的多页来源或按原页边界拆分，同时保持块引用、学习记录和检索一致；本轮没有用猜测页码的方式改写现有内容。

## OCR 配置对照

原导入逻辑为 `ocr: !has_text_layer`：五份有文字层 PDF 关闭 OCR，扫描版黑箱开启。单页对照仍使用 App 实际的 MinerU 上传、查询和下载接口，凭据留在 Android 安全存储。

对照页：AFML p.62、114；机器学习实战 p.256、663；利率讲义 p.15；因子投资 p.58；黑箱 p.80。

关闭 OCR 的单页实验复现了三个关键错误，说明这些错误在 MinerU 输出阶段就已发生，并非 App 的目录构建或数学排版制造。开启 OCR 是有直接证据支持的改进。图像输入在这些样本上未显示额外优势，无需把全书都转成图片再上传。尚未重新验证 p.17、p.681 以及全书所有错误页，不能把三个修复样本推广为“全书公式已正确”。

## 本轮已落地与尚未解决

本轮修复纳入 [v0.0.16](releases/v0.0.16.md)，**v0.0.15 APK 不包含这些改动**：

- PDF 导入默认开启 OCR，包括已有文字层的 PDF；用户仍可主动关闭。EPUB 继续本机解析。
- 导入页移除“书有文字层，一般不需要”的误导提示，改为说明 OCR 对公式和符号的帮助，关闭时给出对应说明。
- 原页兜底文案改为“此页未生成独立的可读内容，已保留原页图像”，避免把跨页合并误报成识别失败。
- 补充两类 PDF 默认开启及手动关闭后切换模型仍保留选择的回归测试。`npm run check`：**116 套件、2,104 项测试、15 个快照通过**，ESLint、TypeScript 通过。
- 在专用 Android 模拟器中打开真实 PDF 单页的导入设置，确认默认开启、关闭后的说明及切换模型仍保持关闭。新提示与开关无遮挡：[导入设置截图](evidence/ocr-audit-20261102/import-settings.jpg)。未点击开始解析。

尚待处理的优先级：

1. **现有数学书的内容修复。** 新默认只影响新导入；现有六本不会自动重算。应优先在可保留学习记录的重解析流程中更新 AFML、机器学习实战和利率讲义，再核对数学高风险页。
2. **跨页来源与页眉误分类。** 保存准确的多页来源，恢复 p.663 这类真实脚注；不能通过全量保留页眉或盲目复制前页内容来处理。
3. **公式编号和双栏顺序。** 需要结合布局证据处理，开启 OCR 本身未解决因子投资 p.58 的问题。

原验收中 17 个 AI 引用通过，说明引用指向了存在且获准使用的内容块；**它不证明内容块里的原始数学符号正确**。伴读模型能读到这些 OCR 错误，不能用流畅的讲解替代原页核对。

## 证据位置与复核范围

私有目录：`fixtures/private/downloads-20261102/`。

- 原始 18 个结果包：`raw/<书籍>/part-N/`；入库快照：`after/<书籍>-result.json`。
- 本轮单页实验：`ocr-audit/raw/<模式>-<书籍>-<页码>/`；提交与最终查询状态：`ocr-audit/jobs.json`、`ocr-audit/status.json`。
- 全量扫描指标：`ocr-audit/quality-metrics.json`；测试日志：`ocr-audit/check.log`。
- 渲染了 47 页供定位，其中实际视觉核对包括上文所列页面、机器学习实战的跨页续行局部、因子投资 p.79 和 p.164 局部、AFML p.370。没有把全部渲染页都计作已人工核验。
- 原生 PDF 文本与相邻 OCR 内容的字符片段覆盖比较仅用于寻找可疑页。图表占比、字体编码、公式表达和跨页合并都会影响覆盖值，因此不把它当作 OCR 准确率。
