核心用户任务：打开手机接上上次学习 → 读原文/听讲 → 核对出处 → 留下笔记、进度、复习材料。评判依据是这条路径是否能完成、能理解、能恢复，而不是功能数量。保留五套皮肤及纸感“伴读 / 原文”的既定风格。

## PM 体验审查

方法：原生 Android 设计审查；web detector 不适用。源码、既有原生截图与本轮模拟器走查分别作为证据，测试结果见下。采用 impeccable 的原生方法，无独立 web 检测子任务。

优先问题：

1. **用户自己的内容可被无关操作删除。** 取消颜色同时删除段落笔记；已学旧章节在重看后退回在学；一次笔记写失败阻塞全库笔记读取。优先于新增提醒、样式和指标。
2. **默认皮肤不能完成发现与配置过程。** 初次引导仅对 Win11 自动打开；学习记录与问书架的能力跟皮肤绑定。用户切换视觉风格不应改变任务可达性。
3. **失败状态没有下一步。** 没填过 Key 被提示“无效”，没分配模型被提示“请求被拒绝”，导入 PDF 直到排队后才发现 Token 缺失。把配置缺失提前并提供直达入口。
4. **回到学习现场不可靠。** 快速离开丢阅读位置、长对话缺少早期消息入口、已改偏好不生效。英文搜索及跨书页码错误也妨碍核对来源。
5. **本地优先缺乏备份提示。** 手动导出存在，但用户不知道什么时候该做；不应以弹窗打断正在读书的人。

值得保留：阅读与听讲共用进度、引用可核对原书、AI 写操作先确认、演示数据与个人书库隔离、五套皮肤共用组件契约。

认知负担主要在配置失败时要求用户记住设置路径，以及换皮肤后重新找功能。本轮新增入口都直接命名任务；备份使用书架内提示，不打断阅读，按钮明确保存目的地及包含内容。用户情绪最差的时刻是“记录消失”和“按提示仍无法继续”，先处理这两种失败路径。

新人验收关注：跳过配置仍可进入书架、之后可从“我的”重开引导；缺 Token 能返回原导入草稿。重度读者关注：回看旧节不丢完成度；旧对话可向前查阅；备份后再次进入不反复催促。小屏/大字号关注：动作能换行、文字可读、设置后返回路径不中断。

## 本轮研发范围与验收标准

| 范围 | 最终行为 | 验收 |
| --- | --- | --- |

备份产品决定：复用已有 ZIP 导出，存入 Downloads。包含解析数据与学习记录；不含原书文件和服务密钥，界面说明。外部分享面板的打开/取消不算成功备份。保持手动“含原文件”选项在存储设置中。首次 7 天从最早导入时间计算；这属于本次明确记录的默认策略。

原生走查额外发现并修复两处同路径问题：导入浮层的 RN 点击组件在 Android 上无法稳定打开文件选择器，改用组件库中与底部浮层手势兼容的触点（最近草稿同样处理）；没有讲解计划时不再显示“第 1/0 段”，改为“尚未开始讲解”。

历史分支仅参考分页实现方式，针对当前多对话模型重做接入；没有整枝合并其实验能力与旧版本文件。
