# 非对话 AI 缓存 · 技术方案

日期：2026-11-02。产品规则见 [功能设计](ai-task-cache-product.md)。

## 请求结构

新增任务请求组装函数，保留任务名和 JSON 输出契约：

1. `system`：固定任务规则、输出 schema；只随任务类型和规则版本变化。
2. 第一个 `contextBlock`：稳定目录背景（存在时），标记 `cache: true`。
3. 最后一个 `contextBlock`：当前原文、目标语言和动态约束，标记 `cache: false`。单段引用 ID 和路线图不可拆分组属于动态约束。
4. 固定 user 指令要求按输入输出 JSON。

Anthropic 在固定 system 和目录后设置断点；OpenAI Responses 沿用设备级 `prompt_cache_key`；Chat Completions 保持可兼容的稳定前缀。缓存能否命中受模型最低长度、供应商支持和保留时间影响，不为达到门槛填充无用 prompt，也不对一次性原文强制设置缓存断点。精修已有固定规则 + 动态 payload 的结构，保留现状。

## 本地数据

迁移 0005：

- `ai_task_cache`：`book_id`、`task`、`scope`、`request_key`、`content`、`used_at`；主键为书籍 / 任务 / 位置，书籍外键级联删除。
- `section_translation` 新增可空 `request_key`，保存整节输入身份；保留旧版所有记录。
- Repository 封装读写与 LRU 淘汰，单段及分片共最多 500 条。

`request_key` 使用稳定 JSON 原文相等比较，不引入有碰撞风险的自定义摘要算法。它不作为大型数据库索引。内容包含任务版本、任务请求（原文 / 目录 / 目标语言 / 动态约束）以及解析后的供应商 ID、模型、协议、地址、思考档位、搜索设置。禁止包含 API Key；价格、缓存开关及显示名不参与身份。整节身份包含全部源文本、目录、配置和分片策略版本。

配置从组合根同一 `AiConfiguration` 解析，缓存读取不取密钥。一次整节翻译固定所选模型配置传给各分片。搜索开启时跳过持久缓存。正文精修以当前阅读投影为输入，内容变化自然失效。

## 应用编排

`TaskResultCache` 管理同一会话的进行中任务，完整身份相同的请求共享工作；订阅者独立取消和接收进度，全部取消才中止生成。关闭会话沿用会话取消流程。

单段解释 / 翻译及整节翻译先查询持久结果，未命中再请求网关。翻译分片逐片保存完整答案；整节内容全部完成后原子替换。重新生成跳过整节及分片读取。成功必须满足：未取消、正常结束、JSON 可解析、答案非空；解释还需包含正确块引用且不含其他块引用。缓存失败不把模型错误保存为答案。

已有完整结果只在新的成功结果完成后替换。输入不同的并发工作按各自身份执行；保存前确认自己仍是该位置最新启动的工作，避免迟到旧请求覆盖更新结果。

页面普通打开与“重新生成”传递不同的 `refresh` 值。本地命中仅记录元数据日志，不伪造供应商缓存命中或 token 用量。其他动态任务只改变请求结构，不缓存答案。

整节翻译的 `refresh` 支持三种值：`false` 先查整节与分片；`true` 跳过整节并清理该节旧分片，开始全新生成；`'resume'` 跳过整节、复用这次已完成的分片。强制重译保留旧整节记录，所以失败后普通打开仍可读上一份译文，重试则继续这次新翻译。前置清理仅作用于该节的翻译分片。

结果回调携带可选 `fromCache` 标记，经 ViewModel 传给译文展示组件，用于完整显示命中结果并跳过动画。缓存只保存原始答案字符串，不持久保存渲染结构或供应商原始响应。只有实际网关调用写入 `ai_usage`。
