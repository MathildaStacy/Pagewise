# 非对话 AI 缓存 · 功能设计

日期：2026-11-02。范围：Pagewise 本地阅读中的翻译、单段解释及非对话任务请求结构。

## 产品判断

值得做。读者反复打开同一段翻译或解释时，希望立即看到上次结果；每次重新生成会打断阅读、重复付费，并造成措辞漂移。缓存命中不需要联网，也不需要重新验证 API Key。

现状不是完全没有缓存：整节译文已有 SQLite 持久化，导读、路线图和压缩摘要也已有业务保存。网关默认启用供应商缓存参数，但大多数任务把变化的原文和目录一起塞进 system，难以复用稳定前缀。单段翻译和解释没有结果复用；整节译文仅检查原文，未区分模型配置。

## 本期行为

| 场景 | 行为 |
| --- | --- |
| 再次打开同一段翻译 / 解释 | 原文、目录、任务规则和模型配置相同，立即显示完整结果，不发 AI 请求 |
| 再次打开整节译文 | 相同输入与配置时复用整节完整译文，重启后仍有效 |
| 重新翻译 / 重新解释 | 跳过已保存结果，按当前模型生成；成功后替换，失败保留旧完整结果 |
| 长章节中途失败 / 停止后重试 | 复用已完整生成的分片，未完成分片重新请求；半截输出不保存为成功结果 |
| 修改原文、采纳 / 撤销精修、目录变更 | 按当前内容重新匹配，不能命中不同内容的结果 |
| 切换模型、供应商地址、协议、思考档位 | 不复用旧配置的结果；同一位置保存最近一次成功版本 |
| 开启联网搜索 | 不持久复用结果，避免把过去的外部搜索答案当作新结果 |
| 同时请求同一结果 | 合并为一次工作，各调用者独立接收流式文本；最后一位调用者取消才停止底层请求 |
| 删除书籍 | 删除书籍关联结果；缓存随本地数据库备份 / 恢复 |

不新增用户配置开关，不自动预翻译，也不改对话问答行为。保留已有“重新翻译 / 解释”入口。导读、路线图、学习小结继续使用其现有业务保存与更新流程，不统一套长期答案缓存。

译文命中本地结果后直接完整显示，跳过逐字动画。停止后按钮为“继续翻译”，失败后为“重试翻译”，两者续做分片；成功后按钮为“重新翻译”，开始全新生成。解释中的未核实引用仍沿用既有展示方式，但这类结果不保存进缓存。

## 容量与升级

单段与翻译分片共保留最近使用的 500 条结果。整节译文继续使用已有表，每节保留一份完整译文。缓存不按时间过期，依赖输入一致性和容量淘汰。旧版整节译文没有模型和提示词身份，升级后保留数据，但首次使用时重新生成可验证的新版本；失败不删除旧数据。

## 验收

1. 单段翻译、解释及整节翻译：第二次请求不调用模型，重建会话后仍可命中。
2. 原文、目录、模型、地址、思考设置变化均不能错误复用；价格、服务显示名变化不影响命中。
3. 重新生成必定请求模型；失败、取消、拒答、截断、空答案或错误 JSON 不替换完整结果。
4. 长章节失败后重试只请求尚未完成的分片，整节结果只在全部完成后保存。
5. 并发请求只产生一次生成，单个调用者取消不影响其他调用者。
6. 固定 system 不随原文变化；稳定目录先于变化内容发送；供应商不支持缓存参数时沿用现有降级。
7. 本地命中不写新增 token 用量。日志只记录任务类型和书 ID，不记录原文、答案或缓存身份正文。

收益以“避免的远程调用、实际缓存读写 token、重复打开等待时间”衡量，不预设供应商命中率或节省比例。
