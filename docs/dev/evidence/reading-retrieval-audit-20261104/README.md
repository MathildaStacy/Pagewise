# 书页、翻译、AI 讲解与上下文检索的 10 项优化

2026-11-04，Pagewise，基于 `dadbdb5`（v0.0.22）。

用 Pixel 10 Pro 只读模拟器（`emulator-5582`，1280 × 2856）实测《因子投资：方法与实践》（中文 PDF）、*ML-Trading*（英文 PDF），并在验收脚本里记录每次发给 AI 的完整请求（系统提示、上下文块、历史与工具），据此核对检索与上下文问题。验收脚本与原始请求保留在忽略目录 `fixtures/private/pm-review-20261104/`。

## 问题与改动

| # | 体验 / 检索问题（实测） | 已完成的优化 |
| --- | --- | --- |
| 1 | 从地图「看原文」或岔路进入的小节读到底是死胡同：「读完这一节」只对主线小节显示，想接着读只能退回地图。 | 非主线小节末尾显示「下一节 · 3.5.3 动量因子实证」，并提示「伴读仍停在 1.1.1」；点开在原文模式接着读，不改主线进度。 |
| 2 | 讲解完成后「AI 举例 / 补充推导」默认折叠，只剩标题，像一张空卡片。 | 折叠态显示展开箭头和一行预览，点预览或标题展开。 |
| 3 | 单段「解释」不流式：翻译边出边显示，解释要等整段 JSON 回来，实测 10–20 秒只有转圈。 | 解释改为流式显示，缓存命中仍一次给全。 |
| 4 | 逐段翻译互相看不到上下文：每段只带本段和全书目录，同一节里术语、指代前后不一致。 | 每段另附「本段所在小节 + 上一段原文与译文」作参照，只用于保持一致、不翻译它们。参照不进缓存键，已有译文继续命中。 |
| 5 | 单段「解释」只拿到这一段：不知道它在 3.5.2，没有前后段；随附的 7.6 KB 目录只有 id/标题，混着封面、版权信息、「上架建议：投资理财」。 | 带上章节路径、页码、本节导读一句话（已生成时）、前两段和后一段；目录精简为「各章标题 + 当前章完整小节」，标出「← 当前」，去掉资料类节点。实测 3.5.2 首段的上下文由 8,465 字符降到 2,096 字符。 |
| 6 | 解释图、表、公式和「如表3.19所示」时拿不到实物：图片块文字为空（图题是单独一块），表格只发扁平文字，AI 重绘数据未发，段内提到的图表公式也不会带上。 | 表格发 HTML 和表题，图发图题和重绘数据，图题块带上它说明的图表；段内提到的「表3.19」「图3.20」「式（3.1）」在本节及前后两页里按编号找到后放进 refs。实测「如表3.19所示」一段带上了表3.19 的 HTML。 |
| 7 | 长段落只能整段讲、整段问：一块常有 600–800 字（3.5.2 首段列了 8 种学说），「解释」只能 200 字概括全段，「带到伴读里继续问」也只能引整段。 | 解释面板「只讲一句」逐句列出，点一句只讲这一句（整段仍作上下文），可「讲整段」返回；带到伴读时引用条和对话气泡显示这一句，`<turn>` 写入 `quote_focus`。 |
| 8 | 从书页问别的小节时上下文错位：伴读先给主线 1.1.1 整理路线图（多一次 AI 调用，书架「继续学习」也变成 1.1.1 第 1/5 步）；`<turn>` 仍是主线位置，与「只讲 turn 指定的这一步」冲突；书的地图只展开主线所在章。 | 引用其他小节的提问不再先规划主线；`<turn>` 写明 `detour_section` / `detour_title`，讲解规则说明岔路里按该小节回答；书的地图同时展开岔路所在章。 |
| 9 | 每轮 `<turn>` 被拼了两次：用户消息已带 turn，组装上下文时又追加一遍，token 估算也重复计算。 | 已带 turn 的用户消息不再追加，估算同步修正。 |
| 10 | 全书搜索（AI 的 `search_book`，也用于地图搜索）召回差：整句按一个短语匹配，「动量 崩溃 尾部风险」0 条；两字词「动量」按书序取前 8 条，全是前言和第 1 章的零散提及；英文「momentum crashes」参考文献排第一；按章过滤在取完 8 条后才做，章号「1」会匹配 10.x。 | 按空格拆成多个词（OCR 式单字空格仍合并），至少命中一半词，按命中词数、出现次数排序，标题加权；按章过滤下推到查询里并按小节树精确匹配（接受「3」「ch3」「第3章」「3.5 标题」）；工具层把参考文献、目录等资料类小节排后，并返回小节标题。实测「动量 崩溃 尾部风险」返回 3 条，前两条在 3.5.2；「动量」前 8 条全部来自 3.5.1–3.5.2。 |

## 原生验收

两个已配置的 AI 服务（starhubapi、xcpcai `gpt-6.1-sol`）在本机直接调用也返回「无效的令牌」，因此未取得在线回答。上下文检索以设备上实际组装的请求为准；界面状态（流式、逐句、引用、翻译参照）在请求记录之后改由应用自带的 Demo 回复驱动，Demo 不理解 `focus`，回答内容不代表真实模型效果。

- 单段解释：3.5.2 首段请求含章节路径、前后段、精简目录；逐句选择后请求含 `focus`；3.5.3「如表3.19所示」一段的 refs 含表3.19 HTML 与表题；图3.20 的图片块带图题。
- 带引用提问：引用条和气泡显示所选句子；请求最后一条用户消息只有一个 `<turn>`，含 `quote_focus`、`detour_section: 3.5.2`；书的地图包含 3.5.1 / 3.5.3。
- 翻译：第 2 段起请求顺序为「缓存的目录 → 参照（小节标题、上一段原文与译文）→ 本段输入」。
- 3.5.2 读到底出现「下一节 · 3.5.3 动量因子实证」，点开进入 3.5.3 原文。
- ML-Trading 的 L2 讲解里，折叠的「AI 举例」显示箭头与一行预览。

宿主机负载很高（load average 30–60），模拟器响应慢；截图只做等比缩小。

## 后续可做

- 中文书的「翻译本节」仍固定译成简体中文，对中文原书没有意义，可按原文语言改为译成英文或隐藏入口。
- 单段解释的 refs 只在本节和前后两页内按编号查找；跨章引用（如「见第 2 章式（2.5）」）还需要全书按编号索引。
