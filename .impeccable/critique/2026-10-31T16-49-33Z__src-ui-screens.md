# main 视觉设计补充审查

基线：`b213f6d` / v0.0.11；补充日期：2026-11-01。模式：Read（读书、听讲、翻译、笔记正文）+ Operate（书架、目录、复习、设置）。使用 Impeccable critique 的原生设计审查方法。

## 设计结论

**五套皮肤已有明确风格，值得保留；主要的提升空间是让阅读内容成为视觉中心，并把材质、排版和次级页面的细节收齐。** 书架、目录和设置的整体完成度高于阅读工具区。当前的精致感时有被三类细节打断：同屏操作层级过多、用过淡的文字制造轻盈感、共享页面没有完全适配某些皮肤的底材。

以下包含设计判断，并非每项都是程序错误。对比度、控件位置和源码行为另给出量测或证据。没有用一个主观“颜值分”代替审美说明，也没有把上一份报告的 12/20 技术评分当成审美评分。

## 五套皮肤的判断

| 皮肤 | 值得保留 | 最有价值的精修方向 |
| --- | --- | --- |
| 纸感 | 暖纸底、衬线原文、墨蓝强调，最贴近安静的技术书阅读 | 减少阅读页条带；提高页码与辅助文字清晰度；保留纸面和细线的克制感 |
| 苹果风 | 大标题、inset 分组、胶囊与悬浮材质连贯，书架和设置完成度较高 | 悬浮导航增加足够的底色/遮蔽，避免底层文字穿入标签；收敛阅读工具区的胶囊密度 |
| Meta | 紧凑、扫读快，蓝色操作和 Messenger 气泡容易识别 | 继续学习、卡点、AI 三种强调分清主次；统一“我的书”与“最近对话”等同级标题的排版角色 |
| 新谷歌 | 表面层级最克制，M3 选中态清楚，正文与操作容易分辨 | 保护小屏标题和正文空间；不要继续给安静的页面增加额外装饰或卡片 |
| Win11 | Mica、Fluent 彩色图标、Copilot 渐变有完整辨识度；“今天”页有自己的构图 | 复习等共享页面让底材连续；同一行按钮对齐；阅读时降低工具区的块面数量 |

这些是本轮实屏对照的设计判断，不是五套皮肤的客观排名。苹果风在 Android 上的风格，以及 Win11 特有的“今天”和五个导航项，均属于已定方向，不列为缺陷。

## 五项优先设计问题

### V01 · P2 · 阅读页的工具层级抢占了内容的注意力

**可见事实**：同屏常驻顶栏/模式切换、对话与精修/翻译行、原版/重排行及提示。Win11 还保留独立模式选择行。普通字号样本中，应用内容顶端到可见正文起点约 152–198dp，包含这些工具与其上边距；不是整节首屏的固定占用率。听讲底部还常驻完整服务名、模型 ID、推理档位和搜索状态。

**设计判断**：一眼先看到一组工具，再进入原书；多个胶囊、实色块和蓝色文字处于相近的视觉等级，持续提醒用户“可以操作什么”。对 5–15 分钟精读场景，这削弱了进入内容时的连贯感。

**建议**：保留返回、章节定位和读书/听讲的主层级。让精修、翻译、对话管理成为同一个清楚的次级工具层；阅读滚动时可收起次级行，恢复入口保持可见。模型入口显示简短模型名，详情在现有设置面板里展开。Win11 保留 SelectorBar 的位置与风格，通过收拢其他行改善密度。不要靠缩小触控区域换空间。

证据：[纸感阅读](visual/paper-light-read.png)、[苹果风阅读](visual/glass-light-read.png)、[Win11 阅读](visual/win11-light-read.png)、[布局记录](visual/layout-measurements.json)。源码：[StudyView.tsx](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/StudyView.tsx:162)、[ReaderView.tsx](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/ReaderView.tsx:288)、[AiOptionsControl.tsx](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/AiOptionsControl.tsx:97)。适合 `$impeccable distill` / `$impeccable layout`。

### V02 · P2 · 部分“轻”的文字实际过淡，深色图像也未达到同等完成度

**量测事实**：用项目自身的 alpha 合成与 WCAG 对比度函数，读取十套明暗 token。页码色对实际纸面色的结果如下；普通小字的参照值为 4.5:1。

| 页码 / 纸面 | 浅色 | 深色 |
| --- | ---: | ---: |
| 纸感 | 2.414 | 6.645 |
| 苹果风 | 1.805 | 2.483 |
| Meta | 3.334 | 4.606 |
| 新谷歌 | 4.528 | 5.186 |
| Win11 | 3.330 | 4.728 |

纸感浅色 `ink3/surface` 为 2.636；苹果风浅色 `ink2/surface` 为 3.620。此次检查的五套原书正文 `paperInk/paper` 均高于 4.5；问题集中在辅助角色，不能概括成“正文全都难读”。[原始数据](visual/contrast.json)也不代表对透明导航所有叠层完成 AA 认证。

**设计判断与建议**：高级感应来自字号、间距和权重的秩序。保留皮肤主色、纸色、渐变与装饰配色，让实际需要读取的页码、说明、未选中标签使用足够清楚的文字角色。透明教材图另提供浅底原图查看；演示图应有合适的深色版本，避免固定深色标注消失。不要自动改写原书图，也不要把透明度豁免当成已达标。

证据：[苹果风深色阅读](visual/glass-dark-read.png)、[Meta 深色阅读](visual/meta-dark-read.png)。这扩展了原报告 U02/U04 的检查范围，不重复计算为新增逻辑缺陷。源码：[纸感 tokens](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/skins/paper/tokens.ts:43)、[苹果风 tokens](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/skins/glass/tokens.ts:43)、[对比度函数](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/kit/color.ts:94)。适合 `$impeccable typeset` / `$impeccable harden`。

### V03 · P2 · 悬浮导航的透字让材质显得不够干净

**可见事实**：苹果风书架的“新对话”、复习页的卡点操作，以及 Win11“今天”页的书架说明，可透到悬浮导航的图标或标签附近。两套都有内容滚动余量；这是重叠时的视觉干扰，不等于下面的条目永久无法点击。

**设计判断**：用户同时看到导航文字和底层内容的字形，视觉层次被压平。毛玻璃的价值是保留背景氛围，同时把前景操作托起来；现在部分位置仍保留太多底层文字细节。

**建议**：保留悬浮胶囊、亚克力/毛玻璃和现有导航位置。提高导航的局部填充与必要的模糊，或在导航下做足够的渐隐遮蔽，让底层文字不穿过图标/标签。浅深色分别校准，不能仅给整体增加阴影。

证据：[苹果风浅色书架](visual/glass-light-shelf.png)、[苹果风复习](visual/glass-light-review.png)、[Win11 今天](visual/win11-light-today.png)。源码：[苹果风 TabBar](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/skins/glass/components.tsx:237)、[品牌 TabBar](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/skins/brand/components.tsx:224)。适合 `$impeccable polish`。

### V04 · P2 · 翻译面板的首屏重心仍然落在原文预览

**可见事实**：新面板已把原文和中文译文分开，方向正确。但收起预览按 180 字符截富文本，标题、独立公式和段落间距仍会占很大高度。普通字号实屏中译文已经接近底部；原报告 1.3 字号样本中，译文正文基本要滚动后才能阅读。

**设计判断**：点“翻译本节”后，用户的视线先经过面板标题、模式/模型行、原文标题和大段预览，才到任务的结果。视觉主次与本次操作的目的不一致。

**建议**：维持“原文在上、译文在下”。为收起原文设置实际行数/高度预算，保留展开入口；首屏应露出译文标题和一段译文正文。公式较高或字号变大时，优先保证这个内容预算，不能只减少字符数。

证据：[普通字号](visual/glass-dark-translation.png)、[原报告大字号](translation-glass-dark-large.png)。演示译文不用于评价翻译质量。此项对应原报告 U03，是设计层面的展开。源码：[TranslationView.tsx](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/TranslationView.tsx:42)。适合 `$impeccable layout`。

### V05 · P3 · Win11 复习页的实色矩形割裂了 Mica 底材

**可见事实**：Win11“今天”、书架和设置是连续的淡色 Mica 底与浮起的卡片；复习页的统计卡后方、开始复习按钮组及卡点标题行仍使用 `t.color.bg` 实色容器。浅色实屏可见横向矩形底板，与周围底材接缝明显。

**设计判断**：这些容器本应负责布局，视觉上却多形成一层没有统一圆角/边界的面，像局部贴补，降低同一皮肤跨页的完成度。

**建议**：布局层尽量透明；只有真正的卡片承担填充、描边和阴影。复习页的统计、图表、主操作、卡点列表遵循同一材质层级与横向边距。保留 Fluent、彩色图标和 Copilot 渐变，不需要重新设计 Win11 风格。

证据：[Win11 复习](visual/win11-light-review.png)、[Win11 今天](visual/win11-light-today.png)。源码：[统计容器](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/ReviewView.tsx:171)、[按钮组](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/ReviewView.tsx:254)、[卡点标题](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/ReviewView.tsx:269)。适合 `$impeccable polish`。

## 三项应继续沿用的设计

1. **原书与 AI 的分工可见。** 衬线原文、无衬线讲解、用户气泡、页码引用和笔记标签帮助读者判断内容来源；当前段的细线定位比给全文不断加大色块更适合技术书。
2. **五套皮肤有自己的构图和控件语言。** 苹果风的 inset 分组、新谷歌的克制表面、Meta 的紧凑密度、Win11 的材质与彩色图标，以及纸感的暖底都能辨认，不需要统一成同一套卡片。
3. **新封面与面板改进有价值。** 真实 PDF 封面让书架更接近实际的个人书库；翻译面板的实色底、原文/译文区分，以及对话列表的当前项与新建入口，是应保留的改进。

## 认知负荷与使用感受

打开书架时，“继续学习”能迅速唤回上下文；进入学习后，多行工具和较长模型信息要求用户再次分辨主次；进入原文正文后，衬线、页码和段落定位又恢复了连贯感。翻译面板的大预览会再次中断这个节奏。最大的设计机会是减少这些过渡中的停顿。

- **单手通勤精读**：需要把注意力留给章节内容；过密的顶部工具和纸感小模式触控区域叠加，增加操作负担。触控问题详见原报告 U01。
- **睡前深色阅读**：正文配色整体成立；浅淡页码及透明图的深色标注会让核对出处更费力。
- **隔几天回来的熟练用户**：续学摘要有帮助；“新对话”、章节、模型信息的主次需要更清楚，避免一眼看到很多状态却没先看到当前任务。

这些是依据产品场景做的专家走查，未冒充真实用户访谈或任务完成率研究。

## 次要精修项

- Meta 的“我的书”在页面样式里加粗为 700，“最近对话”直接使用 headline；两个同级区块的字重不同。应统一角色，继续保留 Meta 的紧凑感。[源码](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/ShelfView.tsx:701)、[对话标题](/Users/boren.fang/Desktop/Personal/Pagewise/src/ui/screens/ConversationList.tsx:174)。
- Win11“今天”同一操作行的“继续听讲”与“读原文”分别为 48dp 与 40dp 高，顶部齐、底部不齐；统一视觉高度与垂直基线会更完整，不削减触控范围。[实屏](visual/win11-light-today.png)。
- 章节标题旁同时放书名、页码、模式及更多菜单，部分皮肤的副标题被省略；应优先保留当前章节和页码，完整书名可在上一级确认。不能靠继续缩小文字解决。
- 备用封面上的英文会出现 `Desig / ning` 断词；真实封面到位后这一情况减少，缺源文件和 EPUB 占位仍值得做更整齐的短标题/排版。它属于占位工艺，不应替代真实书封。
- 闪卡正反面、笔记章节列表和笔记正文的已检查样本层级清楚，没有为了追求“设计感”额外增加装饰的必要。

## 原生稳定性补充观察

**一次前台应用崩溃已经发生，最小触发条件仍待确认。** 在深色下连续切换和走查皮肤期间，Android 记录 `com.pagewise.audit v11` 的 `APP CRASH(EXCEPTION)`；栈为 `android.graphics.LinearGradient.nativeCreate → BackgroundImageDrawable.draw`。与当时设置/书架的 CSS `backgroundImage` 渐变路径相符，但栈不能定位到某个具体 React 组件，不能据此断言所有渐变或所有设备都会崩。

重启后复走纸感 → 苹果风 → 新谷歌 → Meta 没有再次捕获同一崩溃。另有 Meta/新谷歌深色书架的首次捕获出现书籍区域暂未绘出的情况，原生层级仍有条目，重入后显示正常；保留 transient 截图，不用于常态设计对照，也不计为已稳定复现的新缺陷。

证据：[系统应用崩溃记录](visual/android-gradient-crash.txt)。建议下一次修复阶段用 release 包和常用真机验证换肤、字号变化时的渐变绘制，先缩小触发条件，再决定是否将对应 CSS 渐变迁到已有 SVG 渐变组件。此观察独立于五项审美优先级，也未改写原报告的九类已复现逻辑问题数量。

## 后续设计取向

1. V01 的阅读工具层：可选 **滚动时收起次级行** / **统一成一个工具菜单** / **保留常驻但减少块面与文字**。
2. 落地范围：可选 **先做阅读与翻译** / **先做深浅色与材质** / **五套皮肤一起精修**。
